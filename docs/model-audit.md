# 108-model visual audit - 8 September 2026

The [9 September Blender audit](blender-audit.md) supersedes the earlier four-item limitation list and records additional rendering and source-contact findings.

All 108 primary book illustrations were compared with the actual skinned Human mesh from the front, side and rear three-quarter views. The Reference model uses the same skeleton. Each model was revised and the resulting meshes were inspected again. This is a visual reconstruction review, not anatomical certification or verification by the book's author.

The previous automated audit checked body clearance and floor penetration, but those checks allowed incorrect knee and elbow arrangements. The old offline collision optimizer could rotate the bend plane and change the posture. The book authoring path now preserves its explicitly authored contacts and applies only a uniform floor translation. Existing animated Hatha Yoga Pradipika sequences are unchanged.

The 108 poses retain their exact links to the primary EPUB pictures. Added tests protect straight-leg configurations, grounded kneeling poses, deep squats, forearm supports and the distinct arm balances. The original all-model body-clearance and complete-mesh floor tests remain in place.

## Limits

The rig has fixed body proportions and no articulated finger joints. A single photograph does not establish hidden joint depth, contact pressure, entry/exit movement or the complete three-dimensional pose. Four configurations retain specific refinement notes: Garbhasana, Mrgasana, Karna-pidasana and Padangustha-nasa-sparsasana. Every model remains labelled as a schematic reconstruction; no model is labelled perfect or anatomically verified.

## Reproduce the review

Run `npm run author:book`, `npm test` and `npm run build`. Run `npm run audit:meshes -- <output-directory>` to export all 108 posed meshes and their joint positions. With Python, NumPy and Pillow installed, run `python scripts/render-pose-audit.py <output-directory>` to create 18 source-comparison sheets. The renderer uses the application's actual skinned geometry, not generated artwork. Optional second argument: comma-separated section numbers to rerender only their sheets.
